# Dataset Notes

## Source

Dataset: Network operator KPIs time series dataset  
Source: <https://zenodo.org/records/8147768>

## Domain

This dataset contains anonymized and scaled network operator KPI time-series data.

The project uses this dataset as a portfolio-scale telecom network analytics case study.

## Why This Dataset

This dataset is aligned with the project direction because it is closer to telecom/network operations than generic business analytics datasets.

It supports a backend-leaning ML workflow:

- data acquisition
- schema and quality validation
- time-series preparation
- forecasting baseline
- residual-based anomaly detection
- API demonstration

## Planned Canonical Schema

The pipeline will normalize the raw data into the following canonical schema:

| Field | Type | Description |
| --- | --- | --- |
| `timestamp_index` | integer | Relative time index or timestamp-like ordering field |
| `location_id` | string | Anonymized network/operator location identifier |
| `kpi_name` | string | Canonical KPI name |
| `kpi_value` | float | Scaled KPI value |

## Planned KPI Names

The planned canonical KPI names are:

- `aggregated_internet_traffic`
- `downstream_traffic`
- `active_client_sessions`
- `vpn_traffic`

These names may be adjusted after inspecting the raw dataset files.

## Data Handling Rules

- Raw files are stored under `data/raw/`.
- Raw files are not committed to Git.
- Cleaned files are generated by scripts.
- Dataset assumptions are stored in `configs/data_contract.yaml`.
- Any validation failure must stop downstream processing.
- One time-series is identified by `location_id` and `kpi_name`.

## Quality Rules

Initial quality rules:

- required fields must exist after normalization;
- duplicate records are not allowed for the same `location_id`, `kpi_name`, and `timestamp_index`;
- negative KPI values are not allowed;
- KPI values should not exceed the expected maximum defined in `configs/data_contract.yaml`;
- each series must be sorted by time before modeling.

## Limitation

The dataset is public, anonymized, and scaled. It is not private Indonesian operator data.

This project is inspired by telecom network analytics workflows, but it is not a full production NWDAF implementation.
